# 常驻飞书场次同步

目标：按天猫排班，将已成功的直播片段持续追加到用户所有的飞书文档，场次表保存唯一场次记录与链接。

- 使用现有 lark-cli 用户身份和指定文档文件夹/表，独立 systemd 服务运行。
- 服务直接只读 SQLite 获取全量任务；不受 API 分页限制；排班读取复用现有实现，每五分钟刷新。
- 场次身份由直播间、排班开始和结束构成，不因主播文字变化新建；排班变更需核对已存元信息，不静默改归属。
- 持久化场次文档 ID、表记录 ID、各片段摘要与状态。追加前落盘 pending；不确定响应时下轮读回文档验证相同时间戳+文本，完整则确认，部分或未知则标记需核对。
- 同步只追加成功片段，按时间排序。已有待转写/失败片段会让后续等待，避免到达顺序混乱；超时未完成不虚报完成。任务齐备后继续追加。
- 新文档/新记录的请求结果不确定时停止重复创建；记录写入可按唯一场次编号回读恢复。保留人工核对路径。
- 表的状态区分同步中、等待转写、有失败片段、已同步现有录音；后者不是全场录音覆盖承诺。
- 进程锁禁止并发实例；健康 JSON 保存最后轮次、错误数、文档链接，systemd 自动重启。
- 验证：增量、重启、响应丢失、片段乱序、排班边界、同场唯一文档；真实场次写入与重启后重复运行。
