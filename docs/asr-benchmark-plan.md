# 30 分钟四组对比

增加公司 ASR 录后整段转写，与飞书录后组对比。公司 ASR 已用生产服务器验证 /health 为200。通过既有签名音频接口读取测试 WAV，任务仅登记在 live/asr-benchmark、state=benchmark，不进入正式处理和排班文档。

同一次推流、同一份解码后的 PCM：实时 stream_recognize（每 5 秒 final）、每 30 秒 file_recognize、收满 1800 秒后 file_recognize。文件两组使用完全相同的 30 秒音频文件。独立测试目录与进程，正式录制和文档不改配置；测试文本不进入正式 jobs。

服务先等待下一段新推流录音，30 分钟从首个 PCM 样本开始。提前下播则报告实际时长不足，不伪称完成 30 分钟。保存原音频、逐段事件、三组 TXT、JSON 汇总。指标包括首次非空文字、首次 final、最后完成、成功覆盖音频时长、失败/重试和 API 调用数；文本字数不是准确率，没有人工真值不输出准确率。

并发使用同一飞书 app 可能共享限额，报告明确这是同场运行对比，不能把限流差异直接断言为模型性能。录后组在捕获结束后启动，其他组可能尚未追平。每组处理最多持续到采集结束后一小时，等待推流最多两小时，超时有明确状态。

测试进程有独立容器，进度每 5 秒落盘。设置当前任务 heartbeat，在结果完成或失败时汇报，待流/运行中不反复通知。
