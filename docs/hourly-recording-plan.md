# 每小时录制与每日主播文档

目标：连续推流按一小时关闭录制文件，独立 worker 转写已关闭文件，录制下一小时不等待 ASR 或飞书。下播关闭的不足一小时文件也进入队列。ASR 继续按现有安全长度分段，失败保留录音和重试状态。

用户已选择每天一份、按主播分章节。同一主播重复上场时向既有章节尾部插入，不在文档末尾重复建立章节。

文档：支持 session（兼容旧配置）、daily_person（日期＋排班人员）、daily（日期）。每天文档按北京时间分组，场次表仍每场一条，同日同主播可共享文档链接。既有回执继续指向原文档，避免重建或搬迁历史内容。新文档登记独立持久化回执；创建结果不确定禁止盲目重建。

实施与验证：
1. tests/test_live_feishu_sync.py 新增同主播多场共享文档、不同主播分开、每日总文档、重启去重和创建失败保护测试。
2. 新建 daily_documents.py 管理每日文档登记；LiveSessionSync 增加分组参数；feishu_sync_service 从配置读取分组，跨午夜排班按日拆分。
3. 新增小时录制配置示例：RECORD_SEGMENT_DURATION=1h、REALTIME_ASR_ENABLED=false。保持录制与转写进程独立，不把一小时音频直接交给短音频接口。
4. 运行完整测试；用压缩时间的真实推流验证上一段关闭时下一段继续录制，以及同主播不同场次追加同一实际飞书文档。
5. 推送代码并更新服务器配置。只有没有正在直播的推流时重建 media；如有推流，利用 MediaMTX 配置 API 调整后续录制周期，避免中断直播。

限制：每小时结束后还需 ASR 处理时间；排班是归属依据，不是声纹识别。跨交班点的短音频片段有识别边界误差；文档保留时间和归属说明。原始录音持续保留，磁盘容量需纳入监控。
